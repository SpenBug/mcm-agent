# 数模工作流 · 主流程

本文件是数模工坊的**驱动层**：决定先做什么、后做什么、什么算完成。
工具能力（读 PDF/Excel、生成 Word/LaTeX、检索文献）由 `skills/mcm-tools/` 提供，
数据图见 `skills/mcm-figure/`，非数据图见 `skills/mcm-diagram/` —— **按需加载，不在本文件展开**。

---

## 客户必须提供的四类输入

开工前先清点。**缺哪一类就在首次回复里点名要，不要凭猜测开工。**

| # | 输入 | 常见形态 | 缺失后果 |
|---|---|---|---|
| ① | **竞赛赛题** | PDF / DOCX / 图片 / 纯文本 | 无法开工 |
| ② | **格式规范** | 当届官方格式规范 / 参赛须知 / 提交说明 | 只能按通用规范写，**可能整份作废** |
| ③ | **论文模板** | `.docx` / `.tex` / 模板目录 / 官方附件 | 只能自建版式，**可能与官方要求不符** |
| ④ | **赛题数据** | XLSX / CSV / 图片 / 压缩包 / 多附件 | 只能给方法论，**跑不出真实结果** |

### 收料后的动作

1. **材料按四类分别提交**，落在固定的四个子目录：

   | 输入 | 落点 |
   |---|---|
   | ① 竞赛赛题 | `input/赛题/` |
   | ② 格式规范 | `input/规范/` |
   | ③ 论文模板 | `input/模板/` |
   | ④ 赛题数据 | `input/数据/` |

   先列这四目录清点。**某个目录是空的就说明那一类没给**，直接问客户要，
   **不要拿别的目录里的东西凑，也不要猜**。
2. **各写一份清点表**（见「接料建卡」），**明确标出缺失项与待核验项**。
3. **模板与规范冲突时**：以规范为准，并在回复里指出冲突点。

> **不确认的事就标「待核验」。** 尤其是规范里的硬性条款——宁可多问一句，也不要让客户拿到一份会作废的论文。

## 五步主流程

```
① 接料建卡 → ② 建模 → ③ 求解出图 → ④ 成稿 → ⑤ 提交前自检
```

每一步有**明确的交付物**和**通过条件**。前一步没过，不进下一步。

### ① 接料建卡 —— 产出「规则卡」

这是本流程**最重要的一步**，也是和「通用建模技能」最大的区别：
**每个赛届的规则都不同，规则必须先落成一张卡，后面所有动作都以它为准。**

读四类输入，产出 `reports/规则卡.md`：

```markdown
# 规则卡 · <赛事名> <届次>

## 硬性条款（违反即扣分或作废）
| 编号 | 条款 | 原文摘录 | 出处 | 核对日期 |
|---|---|---|---|---|
| H-01 | 论文不得出现单位/姓名/队号 | 「……」 | 附件2 | 2026-xx-xx |

## 版式要求
- 页眉：有 / 无
- 页码：起始页 / 位置 / 编号方式
- 字号行距：……
- 页数限制：……

## 章节骨架（来自客户模板）
| 顺序 | 章节 | 模板占位符 | 备注 |

## 提交物与时间窗
| 环节 | 时间 | 要求 |

## 数据清点
| 文件 | 类型 | 字段/维度 | 缺失情况 |

## 待核验项
- [ ] ……
```

**通过条件**：四类输入都有结论（含「缺失」和「待核验」）；硬性条款逐条有原文出处。

> ⚠️ **规范里的条款逐届修订，不得沿用往届。** 若客户只给了往届规范，在规则卡里明确标注
> 「本卡基于 <年份> 届，当届须重新核对」，并提醒客户。

### ② 建模 —— 产出分析报告

读题目与数据，产出：

- `reports/题目分析报告.md`：子问题拆解、假设、符号表、模型选择与理由、求解思路
- `reports/术语表.md`：全文用词统一（避免同一概念多种叫法）

要求：

1. **先完整理解题目、附件、目标、约束和评价口径**，再形成方案。
2. 每道子问题**最多两个独立模型体系**；同一控制方程在不同近似阶次下的展开算一个模型族，不机械拆分。
3. **避免套用常见简单模型冒充创新**；创新须来自问题结构、数据处理、约束设计、算法改进或验证方式。
4. 不为凑数量重复画共享流程；同一流程只画一次。

**通过条件**：每个子问题都有明确的模型、输入、输出与求解路径；假设都有依据。

### ③ 求解出图 —— 产出可复现结果

产出：`code/` 可运行代码 · `results/` 结果表 · `figures/` 图 · `results/复现清单.json`

**所有计算结论必须来自实际运行结果。禁止编造数据。**
命令必须核对**退出码**，非零就修，不得当作成功。

#### 出图分工（关键，不要搞错）

| 图型 | 例子 | 工具链 | 命名 |
|---|---|---|---|
| **数据图** | 折线、柱状、散点、热图、箱线、雷达、误差曲线、灵敏度曲线 | `skills/mcm-figure/`（论文级 Matplotlib，含可直接 import 的样式模块） | `raw_qN_*` / `process_qN_*` / `result_qN_*` |
| **非数据图** | 技术路线图、子问题流程图、数据处理流程、模型结构图、指标体系图、决策树 | **`skills/mcm-diagram/` 竞赛模式（draw.io）** | `fig_roadmap` / `fig_flow_qN` / `fig_pipeline` / `fig_model` / `fig_index_system` / `fig_decision_tree` |

**非数据图不要用 Matplotlib 手绘**——那类产物不可编辑、样式不受控、也交不出矢量 PDF。

非数据图必须**两张产物都落 `figures/`**：`.drawio`（可编辑源文件）+ `.pdf`（论文引用）。
导出用：

```bash
drawio figures/fig_roadmap.drawio --no-sandbox --disable-gpu --export --format pdf --crop --output figures/fig_roadmap.pdf
```

> **参数顺序是硬要求**：输入文件必须放**最前面**。drawio 用 commander 解析且开了
> `allowUnknownOption()`，未知开关会挤进位置参数数组，输入文件放后面会被当成 `--disable-gpu`。

> 未检测到 draw.io 桌面版时，**如实记录未导出**，不得声称已导出。

**通过条件**：代码可复现（有复现清单）；每个结论都有对应的结果文件；图有 `.drawio` + `.pdf` 两份。

### ④ 成稿 —— 按客户模板产出论文

**用客户提供的模板，不要自建版式。** 模板缺章节时，按规范补齐并在回复里说明。

产出：**`论文.docx` 和 `论文.pdf` 两份都要有**，或客户要求 LaTeX 时 `论文/` + `论文.pdf`。

> ⚠️ **Word 路线也必须导出 PDF** —— 竞赛提交基本都收 PDF。
> 生成完 docx 后立刻转：
>
> ```bash
> python skills/mcm-tools/scripts/mcm_docx.py pdf 论文.docx
> ```
>
> 引擎自动选（LibreOffice 优先，其次 Word COM）。转完**核对 PDF 页数与 docx 一致**，
> 页数对不上说明版式在转换时变了，要回头查。

摘要六要素齐全：**建模思路 / 主要方法 / 模型 / 结果与结论 / 创新点 / 关键词**。

**通过条件**：章节结构与模板一致；图表引用与正文一一对应；摘要六要素齐全。

### ⑤ 提交前自检 —— 逐闸打勾

**这是本流程的收口，也是硬门禁。** 逐条走 `提交前自检.md`，产出 `reports/自检报告.md`。

**任一「致命项」不通过 → 不得声称交付完成。**
格式项不通过 → 修完重跑对应闸。

**通过条件**：致命项全过；格式项全过或在报告里列明未过原因与影响。

## 交付清单

| 路径 | 内容 |
|---|---|
| `reports/规则卡.md` | 本赛届的规则卡 |
| `reports/题目分析报告.md` · `reports/术语表.md` | 建模阶段 |
| `code/` · `results/` · `results/复现清单.json` | 求解阶段 |
| `figures/*.drawio` · `figures/*.pdf` | 图表（源文件 + 矢量图） |
| `论文.docx` **+** `论文.pdf`，或 `论文/` + `论文.pdf` | 成稿（**两种格式都要**）|
| `reports/自检报告.md` | 提交前自检结果 |

## 通用协议

1. **首次进度更新**回显：已激活本流程、工作区、赛事与届次、计划读取的入口文件。
   未确认的官方规则明确标为**待核验**。
2. **开始每个环节前实际读取**对应文件。知道路径不等于已执行。
3. **已有工具时禁止手写替代实现。** 把任何校验预警视为**未完成**。
4. **环境缺引擎、依赖或渲染器时报告阻塞**，并继续完成仍可验证的部分；
   禁止静默换工具、跳过验证或用较差产物冒充完成。
5. **交付前跑完全部门禁。** 任一命令未运行、退出码非零、或仍有未处理问题时，
   不得声称「已完成」。
6. **最终回复列出**：实际读取的入口、实际运行的关键命令与退出码、核心质量指标、仍存在的阻塞。
   不要只说「已检查」。

## 附：本流程的边界

- 本流程是**方法论与门禁**，不替代工具。具体工具用法见各自 `SKILL.md`。
- 规则卡里的条款**以客户提供的官方原件为准**；本流程只负责组织与核对，不产出规则。
- 不承诺获奖或评审结果。它只帮客户避免「整份作废」与「取消资格」这一类**可完全避免的损失**。
