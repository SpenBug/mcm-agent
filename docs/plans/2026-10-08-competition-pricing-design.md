# 赛事日历 + 按赛事定价 + 商用修复 设计说明

日期：2026-10-08　状态：已获用户确认（brainstorming 两轮问答）

## 背景与目标

数模工坊（mcm-agent）要成为可直接上架销售的商用智能体。三个目标：

1. **按赛事差异化定价**：不同竞赛价值不同，定价应不同（用户决策：按赛事单买）。
2. **赛事日历**：内置 2026 年官方准确比赛时间，顶栏面板展示状态与倒计时。
3. **修复全部 P0/P1 缺陷与文档**：交付即可上架。

成功标准：5 套离线测试 + smoke 全绿；赛事面板显示正确倒计时与状态；发卡工具可签发赛事限定卡；旧卡兼容；README/LICENSE 与实现一致。

## 现状与约束

- 授权体系：Ed25519 离线签发（`keys/license-private.pem` 签、客户端内嵌公钥验），凭证 payload 含 `card/machine/edition/expireAt`，无服务器、无吊销。
- 体验版 2 小时，锚点只在 `license.json`，可删文件重置（缺陷）。
- `docs/体检报告-2026-10-07.md` 列出 P0×7、P1×18、P2 若干；已修 6 项，其余未修。
- 本机 `drawio` 不在 PATH；技能文档仍有 29+ 处 `python skills/...` 相对路径。
- 国赛 2026 起施行《人工智能工具使用规定》：须在参考文献前加"AI 工具使用声明"，支撑材料附《AI 工具使用详情.pdf》；数维杯 AIGC 占比 >30% 取消资格。
- 竞品锚点：MathModelAgent 桌面买断 ¥99、积分 ¥30 起；ModLab（同名）余额+会员；人工代做 ¥1500-8000。

## 方案对比

### 按赛事定价的授权实现

#### 方案一：凭证绑定赛事（competition 字段）✅ 用户选定
- 优点：复用现有离线发卡与验签体系；`issue.js` 加参数即可；全能包=`competition:"all"`。
- 缺点：继承离线体系的无吊销约束。

#### 方案二：赛事结束即到期
- 优点：防囤积促复购。
- 缺点：用户体感"买到的东西消失了"，售卖页需额外解释。
- 处置：不作为默认，发卡时可用 `--days/--until` 自行选择。

#### 方案三：账号 + 云端授权
- 缺点：需自运维服务器，与离线卡密模式冲突。否决。

### 赛事日历呈现

#### 方案一：顶栏赛事面板 ✅ 用户选定
- 内置 JSON（官方准确时间），倒计时与状态按当前时间实时推导，含官网链接与解锁状态。
#### 方案二：面板 + 首页倒计时卡
- 营销感强但首页改动面大，本轮不做。
#### 方案三：联网自动更新
- 需维护服务端，否决（改期时改 JSON 重新打包即可）。

## 推荐方案（已确认）

方案一授权 + 方案一日历 + AI 声明生成器 + P0/P1/文档全部修复，四件全部纳入本轮。

## 详细设计

### 架构

```
src/main/competitions.js      赛事数据（内置）+ 状态推导 + 查询 API
src/main/license.js           payload += competition；试用锚点绑机器码
src/main/ipc.js               competitions:list / set-current；门禁补 session:load
src/main/agent/prompt.js      注入 drawio 绝对路径、当前赛事上下文
src/main/agent/ai-declare.js  AI 工具使用声明生成器（国赛/华为杯规则）
tools/issue.js                --competition 参数 + 台账列 + 价目表
src/renderer/app.js           顶栏 📅 赛事面板、解锁引导、到期文案
resources/skills/**           29+ 处 python skills/ → 绝对路径
scripts/smoke.js              授权状态前置处理
```

### 关键组件

**赛事数据（价目表 = 用户确认的定价）**

| id | 名称 | 定价 | 2026/2027 时间（官方） |
|---|---|---|---|
| cumcm | 国赛 CUMCM 高教社杯 | ¥69 | 2026-09-10 18:00 → 09-13 20:00（已结束；2027 待公布） |
| huawei | 华为杯研究生赛 | ¥79 | 2026-09-23 08:00 → 09-27 12:00（已结束） |
| mcm | 美赛 MCM/ICM | ¥79 | 2027 年 1 月底（待官方公布） |
| apmcm | 亚太赛 APMCM | ¥49 | 2026-06-12 18:00 → 06-15 20:00（已结束） |
| shuwei | 数维杯秋季赛 | ¥39 | 2026-11-20 09:00 → 11-24 09:00，报名截止 11-20 06:00（报名中） |

状态枚举：`open（报名中）/ live（进行中）/ ended（已结束）/ tba（待公布）`，由 `startAt/endAt/regDeadline` 与 `now` 推导，时间均为本地时区。

**授权扩展**
- payload 新增 `competition: string`；缺失（旧卡）→ 视为 `"all"`（老买家兼容，写死并测死）。
- 体验期不受赛事限制；激活后按当前赛事校验，未解锁弹购买引导（该赛事价 + 全能包价）。
- 激活成功文案带出解锁赛事与档位。

**试用锚点绑机器码**
- `trialFirstRunAt/trialLastSeenAt` 迁移写入 `machine.json`（含机器码），`license.json` 只作镜像；删除单个文件不再重置；两处机器码不一致按新机器处理。

**AI 声明生成器**
- 论文导出流程末尾：按国赛 2026 规定生成"AI 工具使用声明"章节（参考文献之前）+ `AI工具使用详情.pdf/.md` 草稿（工具名称/用途/提示方式/采纳核验四栏，留待用户补全）；华为杯按其引用来源规定生成对应附注。

### 数据流 / 接口

```
启动 → competitions:list → 渲染层渲染面板（状态/倒计时由主进程推导）
用户 → 点"设为当前赛事" → competition:setCurrent → config.currentCompetition
发卡 → issue.js --competition cumcm → payload{competition:"cumcm"} → 卡密
激活 → license:activate → 验签 + competition 落库 → 门禁按当前赛事放行/拦截
导出 → ai-declare.generate() → 论文声明节 + 使用详情草稿
```

### 异常与边界处理

- 旧卡无 `competition` → `"all"`；`all` 卡解锁任何赛事。
- 赛事时间缺失/异常 → 状态 `tba`，面板不崩溃。
- 体验期不按赛事限制；到期/未解锁提示区分（付费卡过期 ≠ 体验结束）。
- smoke/promo 跑前备份授权状态、跑后恢复，测试不依赖本机试用剩余。

### 测试策略

- 新增断言：删 `license.json` 不重置试用；赛事 4 种状态推导（注入固定 `now`）；旧卡 = all；新卡赛事不匹配被拦；面板 IPC 往返；smoke 恢复 12/12。
- 回归：`test:tools / test:loop / test:license / test:modeling / test:snapshot / smoke` 全绿。
- 打包验证：赛事面板、brand、四技能进包；私钥不进包。

## 风险与待确认项

- 美赛 2027 官方时间未公布 → `tba` 占位，后续改 JSON。
- 后续发卡默认有效期（是否默认"赛事结束+7天"）留给卖家按需用 `--days` 控制，不强制。
- 渲染层改动无自动化测试 → 保留人工验证清单（多轮工具中断继续、面板倒计时、解锁引导）。
