## 一、P0：现在就是坏的，买家会直接踩到

### 1. 技能库运行时用的是过期副本 —— 体验版水印实际不生效 ✅

`src/main/paths.js:40-60` 的 `syncSkills()` 用「版本号 + `resources/skills` **目录本身**的 mtime」做指纹。改技能库里的**文件内容**不会改父目录 mtime，于是复制永远不触发。

实测差异（仓库 vs 应用真正读取的 `C:\Users\92182\AppData\Roaming\数模工坊\skills`）：

```
stamp: 1.0.0|1791299147391   ← 对应 resources/skills 目录 mtime 2026-10-06 12:42
文件数：仓库 167 | userData 169（多 .stamp + __pycache__）
diff：mcm-figure/scripts/mcm_style.py   不同（仓库 20:50 | userData 13:16）
      mcm-tools/scripts/mcm_docx.py     不同
```

差异内容正是**整块体验版水印实现**：`mcm_style.py` 的 `stamp_watermark()`（第 162-183 行）与 `mcm_docx.py` 的 Word VML 真水印（第 212-280 行）在运行时副本里**完全不存在**。`userData/.../__pycache__/mcm_style.cpython-313.pyc` 时间戳 22:11 —— 证明应用导入的是过期副本。

后果：① 你本机开发与冒烟看到的"已装 8 项、水印正常"都是假象；② **发布新版本如果不 bump `package.json` 版本号，老用户装的 exe 会继续用旧技能库**（水印、规范、模板全都停留在旧版）。

改法（任一即可，建议 ①+②）：① 开发态（`!app.isPackaged`）直接用仓库 `resources/skills`，不同步；② 指纹改成对整棵 `resources/skills` 递归求 `(路径,大小,mtime)` 的哈希；③ 每次发布 bump 版本号。

`src/main/agent/prompt.js:37` 明确写「`run_command` / `run_python` 必须用**绝对路径**，写 `skills/...` 必然找不到文件」，但同一份提示词下面的示例全是相对写法：

### 3. `edit_file` 会改写含 `$` 的新内容 —— LaTeX 公式被吃掉 ✅

`src/main/agent/tools.js:319` 非 `replace_all` 分支用 `text.replace(oldStr, new_string)`，`String.prototype.replace` 会把替换串里的 `$$`/`$&`/`` $` ``/`$'`/`$n` 当模式展开。

实测（临时目录，已清理）：

```
写入 "$$\n\\alpha_1\n$$"  →  实际落盘 "$\n\\alpha_1\n$"      （LaTeX 行间公式被改成行内）
写入 "价格$$数量 $& 结束" →  实际落盘 "价格$数量 X 结束"      （$& 被替换成匹配到的原文）
```

论文手大量用 `$$ ... $$`，这是静默的内容损坏。改法：两个分支都用 `split/join`。

### 4. 多轮工具循环会拼出非法消息历史，中断后会话直接废掉 🔍 + ⚠️

- `src/renderer/app.js:1084` 的 `turn_end` 把 `currentAssistant` 置空却**不复位 `assistantPushed`**（只在 `send()` 里复位，`app.js:949`）。于是第 2 轮起：`app.js:1014` 重建 assistant 对象 → `app.js:1033` 因 `assistantPushed` 仍为 true 跳过入列 → `app.js:1074` 照样 push 它的 tool 消息 → **孤儿 tool 消息**。⚠️
- 成功结束时主进程回灌的 `res.messages` 会覆盖本地（`app.js:967`），所以这条只在**运行中途 error/abort** 时暴露：本地脏历史留下，之后每次发消息都 400。
- `src/main/agent/loop.js:56-59`：在工具执行中途 abort 时返回的 `convo` 里，assistant 带 `tool_calls` 但没有配对的 tool 消息；`ipc.js:580-590` 照样落盘并返回 `ok:true` → 会话文件本身就被写坏，重开会话继续 400。🔍
- 附带：`app.js:1014` 重建的对象没有 `reasoning` 字段，第 2 轮起的思考内容丢失。⚠️

改法：`turn_end` 里复位 `assistantPushed`；abort/error 收尾时给未应答的 `tool_calls` 补一条 `{role:'tool', content:'（已中断）'}` 再落盘。

### 5. 两条越界/注入面 🔍 + ✅

- `tools.js:389` `run_python` 的 `args` 直接 `"${x}"` 拼进 shell 命令，引号不转义。✅ 实测：传入参数 `ok` + `" & echo PWNED > <路径>` → 文件真的被创建 = **任意命令执行**。提示注入链（读到的 PDF 正文诱导模型构造参数）可达。改法：Windows 下按 `cmd` 规则转义或改用 `spawn` 数组参数。

### 6. 拖文件落在非槽位区域会把整个界面导航走 ⚠️🔍

`app.js:2098-2100` 在 document 上只 `preventDefault()` 了 `dragover`，**没有 document 级 `drop` 处理**；`src/main/index.js:40` 只注册了 `setWindowOpenHandler`，没有 `will-navigate` 拦截。结果：Chromium 默认行为会把文件 drop 当导航，主窗口变成被 drop 进来的 PDF/docx；同时 `hideDropOverlay()` 只在槽位 handler 里调用（`app.js:2050,2054`），遮罩会一直挂着。改法：document 级 `drop` 兜底 `preventDefault` + `index.js` 加 `will-navigate` 白名单。
