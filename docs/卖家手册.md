# 卖家手册 · 阿一古数模卡密

> 这份**只给你自己看**。里面有私钥相关的操作，别外传。

---

## 一、先搞懂这套东西怎么运转

```
用户下载 exe → 2 小时体验
     ↓ 到期
界面弹出激活页，显示他的【机器码】+ 你的【微信二维码】
     ↓ 用户扫码加你微信，把机器码发给你
你在微信里发收款码收钱 → 用【签发工具】粘机器码 → 出【卡密】
     ↓ 把卡密发回给他
用户粘贴卡密 → 解锁 ✓
```

**没有服务器，所有验证都在本地完成。** 成本 0 元。

> 软件里**不放收款码**了 —— 付款这一步在微信里聊，
> 你能顺便确认对方是真人、也能解释清楚买的是什么。少一张码，界面还更清爽。

**卡密是「只对某一台机器有效」的**——因为里面签了他的机器码。
换台电脑就失效，这就是「一机一码」。

## 二、一次性准备（只做一次）

### 1. 密钥对

```bash
# 已经生成过了，在这里：
keys/license-public.pem    ← 公钥，内嵌在 exe 里（可以公开）
keys/license-private.pem   ← 私钥，⚠️ 只有你有
```

⚠️ **私钥丢了 = 你再也发不出新卡**（已发的卡还能用）。
**把 `keys/license-private.pem` 备份到至少两个地方**（U 盘、网盘、密码管理器）。

⚠️ **私钥泄露 = 任何人拿到它都能自己发卡**，你的生意就废了。
`.gitignore` 里已经排除了 `keys/`，**别手动把它提交到 GitHub**。

### 2. 微信二维码（软件里唯一的码）

把**加好友二维码**存成：

```
resources/brand/wechat-qr.png
```

要求：**正方形、白底、≥400×400**。用户扫码加你，之后沟通全在微信里。

**换码方法**：微信里「保存二维码」得到的是一整张海报，把中间的方块裁出来覆盖这个文件。
项目里有现成的裁剪脚本 `npm run qr:crop`（自动找二维码边界，并用 zxing 验证**真能扫出来**）。

### 3. 收款码（不进软件）

收款码**不再放进软件**了 —— 付款在微信里聊。文件仍然留着：

```
resources/brand/pay-qr.png     ← 文件在项目里，但打包时被排除，用户看不到
```

- 打包规则已排除它（`package.json` 里 `extraResources` 的 `filter` 含 `!pay-qr.png`）
- **你自己留着，用户加微信后直接在聊天里发给他**
- ⚠️ 换收款码**不用重新打包** —— 反正它不在包里

### 4. 联系方式文案

软件界面上**已去掉微信号文字**（用户要求），只保留二维码图片——`resources/brand/wechat-qr.png`。

- 侧栏页脚（`side-foot`）：「使用问题 / 购买找」+「点这里扫码 →」+ 抖音/小红书/B站 `@汉谟拉比法典`
- 激活页（`lock-hint`）：「长按或截图保存二维码，微信扫码加我」

要改这些文案就改 `src/renderer/index.html` 里 `sf-contact` 和 `lock-hint` 两段。
要换码就覆盖 `resources/brand/wechat-qr.png` 再打包（`npm run qr:crop` 可从海报里裁出方块并验证能扫出）。

> ⚠️ 界面上刻意**不写微信号**的原因：文字版容易被截图外传、被陌生人搜到骚扰，
> 而二维码天然要扫码才看得到账号——既方便你控制添加节奏，也更体面。

## 四、日常发卡（每单约 1 分钟）

### 方式 A：网页签发器（推荐，不用敲命令）

**双击 `tools/keygen.html`**，用 Chrome / Edge 打开。

**第一次用**：把 `keys/license-private.pem` 的内容整段粘进「① 私钥」，点「保存私钥」。
之后不用再粘（存在这台电脑的浏览器里）。

**每单只要三步：**

1. 把用户发来的机器码粘进「② 签发一张卡」——带横杠、小写都行，会自动归一化
2. **选赛事**（决定解锁范围与售价）+ 填有效期（天数，或直接选到期日）+ 买家备注
3. 点「生成卡密」→ 点「复制卡密」→ 发给用户

签完会**自动用公钥验一遍**，显示「✓ 自验通过」再发出去，不会发出无效的卡。

> **建议填买家备注。** 它会写进卡里，用户激活后界面上显示「授权给 XXX」——
> 万一有人倒卖，买家会看到别人的名字，当场就能发现。

「③ 已签发台账」存着签过的每一张，可以**导出 CSV**。
⚠️ 台账在浏览器本地，**清了浏览器数据就没了**，记得定期导出另存。

---

### 方式 B：命令行（批量或写脚本时用）

```bash
# 国赛卡，卖到本届结束
node tools/issue.js new --machine 7E84-2A70-F998-6EB7 --competition cumcm --until 2027-09-20 --buyer "张三 微信"

# 数维杯（现在正在报名的那个）
node tools/issue.js new --machine 7E84-2A70-F998-6EB7 --competition shuwei --until 2026-12-01 --buyer "李四 微信"

# 全能包，一年
node tools/issue.js new --machine 7E84-2A70-F998-6EB7 --competition all --days 365 --buyer "王五 微信"

# 不写 --competition 默认就是全能包（all）
node tools/issue.js new --machine 7E84-2A70-F998-6EB7 --days 365
```

输出：

```
┌─ 卡密已生成 ──────────────────────────────────────
│ 卡号      MCM-2026-0005
│ 机器码    7E84-2A70-F998-6EB7
│ 版本      pro
│ 解锁赛事  高教社杯全国大学生数学建模竞赛（售价 ¥69）
│ 有效期    365 天（到 2027-10-08）
│ 买家      张三 微信
└───────────────────────────────────────────────────
下面这段发给用户，让他在软件里粘贴：
eyJjYXJkIjoiTUNNLTIwMjYtMDAwNSIsIm1hY2hpbmUiOiI3RTg0...
```

**把横线中间那一整段复制，发给用户。**

> 机器码带不带横杠、大小写都行，两种方式都会自动处理。
> 用户可能发来 `7e84-2a70-f998-6eb7`，直接粘进去就行。

### 先验一遍再发

网页签发器**自动自验**；命令行想手动验：

```bash
node tools/issue.js verify eyJjYXJkIjoiTUNNLTIwMjYtMDAwNSIs...
```

看到 `签名 ✓ 有效` 再发出去（`verify` 验的是**卡密凭证**，不是卡号）。

> **旧台账会自动迁移**：以前 `issued.csv` 只有 7 列，现在多了 `competition` 列。
> 第一次跑 `list` 或发卡时自动按旧表头重排，老记录的赛事填 `all`，不会串列。

## 六、邀请有礼（朋友减 ¥5，满 3 人送一期）

规则（与软件里显示的、`src/main/competitions.js` 的 `INVITE_RULES` 完全一致）：

- 用户把**邀请码**（= 他自己卡号的后 6 位）发给同学
- 同学购买时报这个码 → **立减 ¥5**
- 同一邀请码累计满 **3 人** → 送推荐人**一期比赛的使用权**

### 怎么记账

```bash
# 同学报来一个邀请码，你确认收钱了，就记一笔
node tools/issue.js invite 260001 --buyer 李四 --competition cumcm --amount 64

# 查看谁的推荐满了、该发奖励了
node tools/issue.js invites
```

`invites` 的输出：

```
邀请码    推荐数   状态        推荐人
260001    3        🎁 可送 1 次   MCM-2026-0001（张三）

⚠️ 有 1 次奖励待发放（满 3 人送一期比赛的使用权）
```

记满 3 人时 `invite` 命令会**自动提醒**你发奖励。发奖励就是再签一张免费卡：

```bash
node tools/issue.js new --machine <张三的机器码> --competition shuwei --days 90 --buyer "张三 邀请奖励" --note "满3人赠送"
```

### 为什么不在软件里做"自动累计解锁"

这是**纯离线应用**。本地记录"谁用了我的邀请码"的话，用户删掉 `license.json`、
或改一个 JSON 字段，计数就直接重置/绕过了——那种"满 3 人自动送卡"防不住任何人，
反而会变成一堆客诉（"我明明推荐了 3 个为什么没送"）。

所以软件端只负责**把邀请码显眼地展示出来、方便截图分享**；
减价和送卡都由你在微信里确认发放。你记账用 `invite` 命令就行，一秒一笔。

> 📁 推荐记录存在 `tools/invites.csv`，和卡密台账 `issued.csv` **分开两个文件**——
> 卡密台账是"一张卡一行"，推荐是"一次一行"的流水，混在一起格式会乱。
> 同样已 gitignore，别提交。

> 💡 改奖励规则（比如减价从 ¥5 改成 ¥8、阈值从 3 改成 5），
> 改 `src/main/competitions.js` 的 `INVITE_RULES`，软件界面会跟着变。

## 七、用户换电脑了怎么办

**卡密绑死了原机器，换机必须重新签一张。**

```bash
node tools/issue.js new --machine <用户发来的新机器码> --until 2027-09-30 --buyer "张三 换机"
```

**建议的换机政策**：每张卡免费换 1 次，第 2 次起收少量费用。
这样既能照顾正常换机的用户，又能挡住「一张卡给全班用」。

在 `issued.csv` 里搜索买家名字，能看到他换过几次。

## 八、常见问题排查

### 用户说「卡密无效」

按顺序查：

1. **卡密是不是复制全了？** 最长的卡密有 260 多字符，微信里容易漏尾巴。
   让用户**从开头一直选到结尾**，别手动拖。
2. **机器码对不对？** 用 `node tools/issue.js verify <卡密>` 看签名；
   再用 `list` 对比一下卡密绑的机器码和用户报的是不是同一台。
3. **用户是不是换电脑了？** 换机后旧卡必失效。
4. **是不是过期了？** `verify` 会显示到期日。

### 用户说「机器码读不出来」

极少数电脑（虚拟化环境、部分品牌机）读不到硬件序列号。
界面上会显示一个**降级后的弱指纹**。

**这种情况要提醒用户**：换系统/重装可能导致机器码变化，届时需要重新发卡。

### 用户把系统时间调回去想续命

**没用。** 体验版记录的是「首次运行时间」，并且只增不减——
把时钟倒回去，剩余时间**不会变多**。

### 用户想破解

说句实在话：**Electron 的前端代码是可读的，决心足够的人能绕过去。**

这套机制挡的是**普通用户和传播盗版的人**，不是专业破解者。
真正有效的防线是：

- 卡密**绑定机器** → 盗版传播出去别人也用不了
- 激活逻辑在**主进程** → 改前端没用
- **私钥不在客户端** → 没人能自己造卡

## 九、安全红线（记牢）

| 红线 | 为什么 |
|---|---|
| **私钥绝不外传** | 泄露 = 任何人能自己发卡 |
| **`tools/issue.js` 绝不发给用户** | 它持有私钥 |
| **`keys/` 不提交 git** | 已在 `.gitignore`，别手动加回去 |
| **`tools/issued.csv` 不提交** | 含买家信息，已 gitignore |
| **备份私钥到两个地方** | 丢了就再也发不出新卡 |

## 十、收款那件事（必须知道）

我查过的**硬事实**：

> **央行规定：个人收款码不得用于经营性收款。** 2026 年金税四期全量监测。

**你现在用个人收款码收软件销售款，严格讲是不合规的。**

不是我要吓你，是这条你必须知道再决定怎么做：

- **短期**：量小、金额小，实际风险有限，很多人这么做
- **中期**：可以申请**个人经营收款码**（不需要营业执照，有费率），比纯个人码规范
- **长期**：量起来后，注册个体工商户 → 正规商户通道 → 才能接自动发卡

**别等到被限制收款了才想这事。**
