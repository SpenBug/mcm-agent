# 卖家手册 · 阿一古数模卡密

> 这份**只给你自己看**。里面有私钥相关的操作，别外传。

---

## 一、先搞懂这套东西怎么运转

```
用户下载 exe → 1 天体验
     ↓ 到期
界面弹出激活页，显示他的【机器码】+ 你的【微信二维码】
     ↓ 用户扫码加你微信，把机器码发给你
你在微信里发收款码收钱 → 用【签发工具】粘机器码 → 出【卡密】
     ↓ 把卡密发回给他
用户粘贴卡密 → 解锁 ✓
```

**没有服务器，所有验证都在本地完成。** 成本 0 元。

> 软件里**不放收款码**了 —— 付款这一步在微信里聊，
> 你能顺便确认对方是真人、也能解释清楚买的是什么。少一张码，界面还更清爽。

**卡密是「只对某一台机器有效」的**——因为里面签了他的机器码。
换台电脑就失效，这就是「一机一码」。

## 二、一次性准备（只做一次）

### 1. 密钥对

```bash
# 已经生成过了，在这里：
keys/license-public.pem    ← 公钥，内嵌在 exe 里（可以公开）
keys/license-private.pem   ← 私钥，⚠️ 只有你有
```

⚠️ **私钥丢了 = 你再也发不出新卡**（已发的卡还能用）。
**把 `keys/license-private.pem` 备份到至少两个地方**（U 盘、网盘、密码管理器）。

⚠️ **私钥泄露 = 任何人拿到它都能自己发卡**，你的生意就废了。
`.gitignore` 里已经排除了 `keys/`，**别手动把它提交到 GitHub**。

### 2. 微信二维码（软件里唯一的码）

把**加好友二维码**存成：

```
resources/brand/wechat-qr.png
```

要求：**正方形、白底、≥400×400**。用户扫码加你，之后沟通全在微信里。

**换码方法**：微信里「保存二维码」得到的是一整张海报，把中间的方块裁出来覆盖这个文件。
项目里有现成的裁剪脚本 `npm run qr:crop`（自动找二维码边界，并用 zxing 验证**真能扫出来**）。

### 3. 收款码（不进软件）

收款码**不再放进软件**了 —— 付款在微信里聊。文件仍然留着：

```
resources/brand/pay-qr.png     ← 文件在项目里，但打包时被排除，用户看不到
```

- 打包规则已排除它（`package.json` 里 `extraResources` 的 `filter` 含 `!pay-qr.png`）
- **你自己留着，用户加微信后直接在聊天里发给他**
- ⚠️ 换收款码**不用重新打包** —— 反正它不在包里

### 4. 联系方式文案

软件界面上**已去掉微信号文字**（用户要求），只保留二维码图片——`resources/brand/wechat-qr.png`。

- 侧栏页脚（`side-foot`）：「使用问题 / 购买找」+「点这里扫码 →」+ 抖音/小红书/B站 `@汉谟拉比法典`
- 激活页（`lock-hint`）：「长按或截图保存二维码，微信扫码加我」

要改这些文案就改 `src/renderer/index.html` 里 `sf-contact` 和 `lock-hint` 两段。
要换码就覆盖 `resources/brand/wechat-qr.png` 再打包（`npm run qr:crop` 可从海报里裁出方块并验证能扫出）。

> ⚠️ 界面上刻意**不写微信号**的原因：文字版容易被截图外传、被陌生人搜到骚扰，
> 而二维码天然要扫码才看得到账号——既方便你控制添加节奏，也更体面。

## 三、价目表（按时长定价）

**一张卡解锁全部功能，不限赛事。** 卡密的 payload 里带 `plan` 字段
（week / month / year / forever）与 `expireAt`，客户端只校验
「签名 + 机器绑定 + 有没有过期」，**不校验赛事**。

| 档位 | 卡密参数 | 时长 | 售价 | 折合每天 |
|---|---|---|---|---|
| **周卡** | `--plan week` | 7 天 | **¥29** | ¥4.14 |
| **月卡** | `--plan month` | 30 天 | **¥59** | ¥1.97 |
| **年卡** | `--plan year` | 365 天 | **¥99** | ¥0.27 |
| **永久买断** | `--plan forever` | 永久 | **¥199** | — |

> 不写 `--plan` 默认 **年卡**（历史默认值，保持老习惯不变）。
>
> **永久买断**没有天数：`expireAt` 写 2099-01-01 哨兵值，payload 另带
> `perpetual: true`，客户端据此显示「永久」而不是一个日期。
> 为什么不加个布尔位让验签跳过过期判断 —— 验签是整条授权链的地基，
> 为一种档位去动它不值得；哨兵值走完全相同的代码路径。

**为什么从按赛事改成按时长**：
- 按赛事时，用户买了国赛卡、想顺手做一道华为杯题就被拦住，看起来像软件坏了，客诉多
- 赛事日历是会变的（加新赛事、改时间），授权逻辑不该依赖会漂移的数据
- 时长制下「买了就能用」，到期自然续费，你不用判断"他这场能不能用"

> ⚠️ **价目表是商业决策，改价只改一处**：
> `src/main/competitions.js` 的 `PLANS`（客户端与四个签发入口共用这一份），
> 改完跑 `npm test` —— 「签发器赛事选项与定价同源」会盯住漂移。

> 💡 **有效期怎么填**：
> - 按档位卖 → 什么都不用填，`--plan month` 自动算 30 天
> - 想卖「到某个日期」→ 用 `--until 2027-09-20`（优先于档位天数）
> - 想卖不规则天数 → `--days 45`（优先于档位天数）
> - 永久买断 → `--plan forever`，别配 `--until` / `--days`（配了会被覆盖成哨兵）

> ⚠️ **旧卡兼容**：2026-10 之前按赛事签发的卡（国赛卡 / 全能包等）**继续有效**，
> 客户端一律按**年卡**口径放行（老买家不受影响，已测）。
> 台账里这些行的 `plan` 列会保留原赛事 id（如 `cumcm`、`all`），
> 不是 bug —— 那是收钱的凭据，对账时要能看出来。

## 四、日常发卡（每单约 1 分钟）

> **三个图形界面，别搞混：**
>
> | | 启动方式 | 卡记到哪 | 建议 |
> |---|---|---|---|
> | **桌面签发器**（独立应用） | 开始菜单/桌面「阿一古数模签发器」 | ✅ 直接写进 `%APPDATA%\阿一古数模签发器\issued.csv` | **最推荐**：有窗口、有快捷方式、能脱离源码目录 |
> | 本地签发器（旧） | 双击 `tools/签发卡密.bat` | ✅ 直接写进 `tools/issued.csv` | 源码目录还在时可用 |
> | 网页签发器 | 双击 `tools/keygen.html` | ⚠️ 只存浏览器本地 | 备用/离线时用，用完必须导一次 |
>
> **三者的签发逻辑完全同源**（`tools/issuer-core.js`），所以卡密格式、赛事价格、
> 排号规则永远一致 —— 有测试（`issuer-consistency-test`）盯着，谁漂移谁红。
>
> 为什么"卡记到哪"要紧：`invite` / `invites`（推荐满 3 人发奖励）只查台账文件。
> 用网页签发器发的卡如果不导进去，**买家来领奖时你查不到他是谁**。

### 方式 A：桌面签发器（最推荐）

**从开始菜单或桌面双击「阿一古数模签发器」**（装的时候自动创建快捷方式）。

它是个**独立应用**，不依赖源码目录，也不起本地 HTTP 服务（走应用内通信，
比旧版少一个攻击面）。五个标签页：

| 标签页 | 用途 |
|---|---|
| **签发** | 填机器码 → 选赛事 → 选有效期 → 签发、复制卡密 |
| **台账** | 全部记录 + 搜索（卡号/机器码/买家/邀请码）+ 导出 CSV + 导入 keygen 台账 |
| **邀请** | 记一笔推荐、看谁快满 3 人该送卡（以前只能敲命令行） |
| **验卡** | 粘卡密当场验签名/机器码/到期 —— 客户说"卡不能用"时用 |
| **设置** | 数据目录位置、清理多余的私钥副本 |

**每单四步**（与旧版一致）：

1. 粘用户的**机器码**（带横杠、小写都行，自动归一化）
2. **选时长档位** —— 这一项决定售价和有效期，别停在默认值
3. 选有效期（天数，或指定到期日）+ 买家备注
4. 点「签发」→ 复制卡密发给用户

> ⚠️ **私钥与台账在 `%APPDATA%\阿一古数模签发器\`**，不在程序目录里
> （装到 Program Files 时程序目录不可写）。换电脑就把这个目录整个拷走。
>
> 首次启动会自动从 `keys\license-private.pem` **复制**一份过去，
> **不会删源文件** —— 私钥丢了就再也发不出新卡，自动删风险太大。
> 确认新位置能用之后，可在「设置」页手动删掉源码目录那份副本。

### 方式 A′：本地签发器（旧，源码目录还在时可用）

**双击 `tools/签发卡密.bat`**，会自动开浏览器到 `http://127.0.0.1:38901`（只监听本机，局域网别人连不上）。

**每单四步：**

1. 粘用户的**机器码**（带横杠、小写都行，自动归一化）
2. **选解锁赛事** —— 这一项决定售价和买家能用哪个赛事，别停在默认值
3. 选有效期（天数，或指定到期日）+ 买家备注
4. 点「签发」→ 复制卡密发给用户

签完界面会回显 **卡号 / 档位与售价 / 邀请码 / 有效期**，同时这张卡已经进 `issued.csv` 了。

> ⚠️ **第 2 步一定要选。** 不选的话默认是年卡（¥199 的权限）——
> 曾经就因为这个界面没有档位下拉，卖 ¥59 的月卡被签成年卡，买家白拿、你亏钱，
> 而且台账上完全看不出来。现在界面有下拉，且有测试钉住这条。

「已签发」表格会显示卡号、档位、机器码、**邀请码**、到期、买家。

> **建议填买家备注。** 它会写进卡里，用户激活后界面上显示「授权给 XXX」——
> 万一有人倒卖，买家会看到别人的名字，当场就能发现。

### 方式 B：网页签发器（离线备用）

**双击 `tools/keygen.html`**，Chrome / Edge 打开。适合手边没有 Node、或在别的电脑上临时发卡。

**每次打开标签页**：把 `keys/license-private.pem` 的内容整段粘进「① 私钥」，点「载入私钥」。
私钥只保存在当前标签页的 `sessionStorage` 里，关闭标签页即清除，不会长期落盘。签完会**自动用公钥验一遍**，显示「✓ 自验通过」再发出去。

⚠️ 用这个界面发卡，**必须做两件收尾**：

```bash
# 1) 在页面点「导出 CSV」，然后把这份记录并进 issued.csv
node tools/issue.js import 下载/阿一古数模-卡密台账-2026-10-09.csv --dry   # 先看清单
node tools/issue.js import 下载/阿一古数模-卡密台账-2026-10-09.csv          # 确认无误再真写

# 2) 反过来，如果命令行发过卡，先导入一次再在这个页面发卡，
#    它才能接着排号、不会签出重复卡号（页面里点「导入 issued.csv」）
```

> 卡号重复不是小事：邀请码 = 卡号后 6 位，两张同号卡就有同一个邀请码，
> `whoIs()` 取第一条匹配 —— **推荐奖励会记到错误的人头上**。

### 方式 C：命令行（批量或写脚本时用）

## 六、邀请有礼（朋友减 ¥5，满 3 人送一期）

规则（与软件里显示的、`src/main/competitions.js` 的 `INVITE_RULES` 完全一致）：

- 用户把**邀请码**（= 他自己卡号的后 6 位）发给同学
- 同学购买时报这个码 → **立减 ¥5**
- 同一邀请码累计满 **3 人** → 送推荐人**一期比赛的使用权**

### 怎么记账

```bash
# 同学报来一个邀请码，你确认收钱了，就记一笔
node tools/issue.js invite 260001 --buyer 李四 --plan month --amount 59

# 查看谁的推荐满了、该发奖励了
node tools/issue.js invites
```

`invites` 的输出：

```
邀请码    推荐数   状态        推荐人
260001    3        🎁 可送 1 次   MCM-2026-0001（张三）

⚠️ 有 1 次奖励待发放（满 3 人送一期比赛的使用权）
```

记满 3 人时 `invite` 命令会**自动提醒**你发奖励。发奖励就是再签一张免费卡：

```bash
node tools/issue.js new --machine <张三的机器码> --plan year --buyer "张三 邀请奖励" --note "满3人赠送"
```

### 为什么不在软件里做"自动累计解锁"

这是**纯离线应用**。本地记录"谁用了我的邀请码"的话，用户删掉 `license.json`、
或改一个 JSON 字段，计数就直接重置/绕过了——那种"满 3 人自动送卡"防不住任何人，
反而会变成一堆客诉（"我明明推荐了 3 个为什么没送"）。

所以软件端只负责**把邀请码显眼地展示出来、方便截图分享**；
减价和送卡都由你在微信里确认发放。你记账用 `invite` 命令就行，一秒一笔。

> 📁 推荐记录存在 `tools/invites.csv`，和卡密台账 `issued.csv` **分开两个文件**——
> 卡密台账是"一张卡一行"，推荐是"一次一行"的流水，混在一起格式会乱。
> 同样已 gitignore，别提交。

> 💡 改奖励规则（比如减价从 ¥5 改成 ¥8、阈值从 3 改成 5），
> 改 `src/main/competitions.js` 的 `INVITE_RULES`，软件界面会跟着变。

## 七、用户换电脑了怎么办

**卡密绑死了原机器，换机必须重新签一张。**

```bash
node tools/issue.js new --machine <用户发来的新机器码> --until 2027-09-30 --buyer "张三 换机"
```

**建议的换机政策**：每张卡免费换 1 次，第 2 次起收少量费用。
这样既能照顾正常换机的用户，又能挡住「一张卡给全班用」。

在 `issued.csv` 里搜索买家名字，能看到他换过几次。

## 八、常见问题排查

### 用户来领奖，但 `invites` 查不到他的邀请码

九成是**这张卡是用网页签发器发的，没并进 `issued.csv`**。

邀请码 = 卡号后 6 位，而 `whoIs()` 只在 `issued.csv` 里找。
去网页签发器「导出 CSV」，再 `node tools/issue.js import <那个文件>`，然后 `list` 复查。

（平时用本地签发器 `tools/签发卡密.bat` 就不会有这个问题——它直接写 `issued.csv`。）

### 两张卡卡号一样 / 邀请码撞了

**后果比看起来严重**：同一个邀请码会让 `whoIs()` 只认第一条，推荐奖励记到错误的人头上。

原因通常是网页签发器看不到 `issued.csv`，从 0001 重新排号。
现在它会按台账里已有的最大序号往后推，但**前提是你先导入一次**：
在网页里点「导入 issued.csv」，之后它就知道排到哪儿了。

真出现重复时：`list` 找出同号的两张，手工把后发的那张改成新号并重签。

### 卖的是月卡，用户却说"我这是年卡"

检查这张卡在 `issued.csv` 里的 `plan` 列是什么。

如果是 `year` 而买家只付了 ¥59，说明发卡时**没在界面里选档位**（默认是年卡）。
这是最容易漏钱的一步，所以现在：签发器有档位下拉且必选、
签完回显售价、`npm test` 里有一条专门盯这个透传。

补救：给用户重签一张正确档位的卡（旧卡不吊销，但你可以告诉他以新卡为准）。

### 用户说「卡密无效」

按顺序查：

1. **卡密是不是复制全了？** 最长的卡密有 260 多字符，微信里容易漏尾巴。
   让用户**从开头一直选到结尾**，别手动拖。
2. **机器码对不对？** 用 `node tools/issue.js verify <卡密>` 看签名；
   再用 `list` 对比一下卡密绑的机器码和用户报的是不是同一台。
3. **用户是不是换电脑了？** 换机后旧卡必失效。
4. **是不是过期了？** `verify` 会显示到期日。

### 用户说「机器码读不出来」

极少数电脑（虚拟化环境、部分品牌机）读不到硬件序列号。
界面上会显示一个**降级后的弱指纹**。

**这种情况要提醒用户**：换系统/重装可能导致机器码变化，届时需要重新发卡。

### 用户把系统时间调回去想续命

**没用。** 体验版记录的是「首次运行时间」，并且只增不减——
把时钟倒回去，剩余时间**不会变多**。

### 用户想破解

说句实在话：**Electron 的前端代码是可读的，决心足够的人能绕过去。**

这套机制挡的是**普通用户和传播盗版的人**，不是专业破解者。
真正有效的防线是：

- 卡密**绑定机器** → 盗版传播出去别人也用不了
- 激活逻辑在**主进程** → 改前端没用
- **私钥不在客户端** → 没人能自己造卡

## 九、安全红线（记牢）

| 红线 | 为什么 |
|---|---|
| **私钥绝不外传** | 泄露 = 任何人能自己发卡 |
| **`tools/issue.js` 绝不发给用户** | 它持有私钥 |
| **`keys/` 不提交 git** | 已在 `.gitignore`，别手动加回去 |
| **`tools/issued.csv` 不提交** | 含买家信息，已 gitignore |
| **备份私钥到两个地方** | 丢了就再也发不出新卡 |

## 十、收款那件事（必须知道）

我查过的**硬事实**：

> **央行规定：个人收款码不得用于经营性收款。** 2026 年金税四期全量监测。

**你现在用个人收款码收软件销售款，严格讲是不合规的。**

不是我要吓你，是这条你必须知道再决定怎么做：

- **短期**：量小、金额小，实际风险有限，很多人这么做
- **中期**：可以申请**个人经营收款码**（不需要营业执照，有费率），比纯个人码规范
- **长期**：量起来后，注册个体工商户 → 正规商户通道 → 才能接自动发卡

**别等到被限制收款了才想这事。**
